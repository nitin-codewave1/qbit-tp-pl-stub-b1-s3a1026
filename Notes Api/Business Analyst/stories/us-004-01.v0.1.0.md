# US-004-01: fetch a published OpenAPI spec that documents every notes_api endpoint

## Definition

As a **integration developer building the web_app front end**, I want to **fetch a published OpenAPI spec that documents every notes_api endpoint**, so that **integrate without backend rework, directly raising % of endpoints covered by published API documentation**.

**Epic:** [[EP-004]]

## Acceptance Criteria
- [[AC-004-01-01]] — Given notes_api is deployed, when client requests the OpenAPI document, then a valid OpenAPI 3.x JSON/YAML document is returned listing all CRUD, tagging, search, archive, and email one-time-code login (send and verify) endpoints
- [[AC-004-01-02]] — Given a new endpoint is added to notes_api, when the spec is regenerated/published, then the new endpoint appears in the OpenAPI document before or at the same time it becomes callable
- [[AC-004-01-03]] — Given the OpenAPI endpoint is requested with an unsupported Accept header, when client requests the spec, then API returns a 406 or a default-format fallback with a clear content-type
