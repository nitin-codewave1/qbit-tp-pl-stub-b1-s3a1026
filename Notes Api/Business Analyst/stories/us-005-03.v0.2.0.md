# US-005-03: ensure no real-time collaboration channel (WebSocket/SSE) exists on notes_api

## Definition

As a **Backend developer implementing notes endpoints**, I want to **ensure no real-time collaboration channel (WebSocket/SSE) exists on notes_api**, so that **avoids building concurrent-editing infrastructure, keeping scope and cost minimal per the KPI**.

**Epic:** [[EP-005]]

## Acceptance Criteria
- [[AC-005-03-01]] — Given the running API server, when a client attempts a WebSocket upgrade or SSE connection to any notes_api endpoint, then the connection is rejected (no protocol upgrade, standard error status returned)
- [[AC-005-03-02]] — Given two clients submit PATCH requests to the same note concurrently, when both requests are processed, then the API applies a standard last-write/conflict response with no live broadcast or merge logic
