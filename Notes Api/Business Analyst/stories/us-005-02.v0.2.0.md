# US-005-02: ensure no attachment or file-upload endpoint exists in notes_api

## Definition

As a **Backend developer implementing notes endpoints**, I want to **ensure no attachment or file-upload endpoint exists in notes_api**, so that **prevents accidental scope creep into attachments, protecting cost/timeline per the guardrail KPI**.

**Epic:** [[EP-005]]

## Acceptance Criteria
- [[AC-005-02-01]] — Given the deployed API route registry, when a request is sent to any attachment path (e.g. POST /notes/{id}/attachments), then the API returns 404 Not Found
- [[AC-005-02-02]] — Given a note create/update endpoint, when a multipart/form-data request with a file payload is submitted, then the API returns 415 and persists no file content
