# US-005-04: receive a clear, documented error when calling an unsupported out-of-scope endpoint (mobile-specific, attachment, or real-time)

## Definition

As a **Third-party client integrator consuming notes_api**, I want to **receive a clear, documented error when calling an unsupported out-of-scope endpoint (mobile-specific, attachment, or real-time)**, so that **avoids wasted integration effort on excluded features and reinforces the documented scope guardrail**.

**Epic:** [[EP-005]]

## Acceptance Criteria
- [[AC-005-04-01]] — Given an integrator calls an out-of-scope endpoint, when the request is made, then the response body includes a message referencing the scope exclusion rather than a bare 404
- [[AC-005-04-02]] — Given an integrator sends a multipart file upload to a notes endpoint, when the request is validated, then the response returns a structured error code (e.g. OUT_OF_SCOPE) with a human-readable reason
