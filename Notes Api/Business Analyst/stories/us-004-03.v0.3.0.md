# US-004-03: see documented error responses (4xx/5xx) for each endpoint in the spec

## Definition

As a **integration developer building the web_app front end**, I want to **see documented error responses (4xx/5xx) for each endpoint in the spec**, so that **handle failures predictably in the client, reducing integration rework and supporting coverage completeness**.

**Epic:** [[EP-004]]

## Acceptance Criteria
- [[AC-004-03-01]] — Given an endpoint can return validation errors, when the spec is reviewed, then a 400 response schema with error structure/fields is documented
- [[AC-004-03-02]] — Given an endpoint requires authentication/authorization or is an email one-time-code login endpoint, when the spec is reviewed, then 401/403 responses are documented with expected body shape, and the send/verify login endpoints document a TBD (asked: Q-BA-627430) response for more than 3 requests within 10 minutes and a locked-account response after 5 wrong codes, locked for 15 minutes
- [[AC-004-03-03]] — Given a documented field type is changed in code, when the 404 response is checked against the spec, then documented 404 response matches the actual API behavior
