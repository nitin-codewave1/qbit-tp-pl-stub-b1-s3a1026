# US-004-02: define request/response schemas (notes, tags, search, archive) in the OpenAPI spec with required fields and types

## Definition

As a **backend developer maintaining notes_api**, I want to **define request/response schemas (notes, tags, search, archive) in the OpenAPI spec with required fields and types**, so that **clients integrate correctly without guessing payload shapes, supporting full endpoint coverage KPI**.

**Epic:** [[EP-004]]

## Acceptance Criteria
- [[AC-004-02-01]] — Given an endpoint accepts a note payload, when the schema is inspected in the spec, then all required fields, types, and constraints (e.g., title length, tag format) are documented
- [[AC-004-02-02]] — Given an endpoint supports optional query parameters (e.g., search filters), when the schema is reviewed, then optional parameters are marked optional with default values documented
- [[AC-004-02-03]] — Given a documented field type is changed in code, when the spec is not updated to match, then a spec-validation/CI check fails, flagging the mismatch
