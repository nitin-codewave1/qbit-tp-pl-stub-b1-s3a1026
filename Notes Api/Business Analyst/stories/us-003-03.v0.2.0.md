# US-003-03: receive search responses within the performance SLA under typical load

## Definition

As a **Integration engineer consuming the search API**, I want to **receive search responses within the performance SLA under typical load**, so that **ensures search stays fast (p95 <300ms), directly meeting the objective's latency KPI**.

**Epic:** [[EP-003]]

## Acceptance Criteria
- [[AC-003-03-01]] — Given a search request under 50 requests per second load, when the request is executed, then p95 response latency is under 300ms
- [[AC-003-03-02]] — Given a large dataset (e.g., 100k notes), when a search is executed, then the latency SLA is still met via indexed lookup
- [[AC-003-03-03]] — Given the search index is degraded or unavailable, when a search is requested, then API returns 503 with a retry-after header instead of hanging
