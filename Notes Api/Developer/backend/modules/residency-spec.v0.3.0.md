## Purpose

**Responsibility.** The `residency` module proves and enforces that every `notes_api` infrastructure component (database, compute, backups) sits in an approved EU region. Sources: BR-001 to BR-004; NFR-001 to NFR-004; `backend.module-map`. It covers six concerns, each with its owning operations:

| Concern | Stories | Operation |
|---|---|---|
| Refuse provisioning in a non-EU region | US-001-01 | `API-RESIDENCY-026899` |
| Validate a backup destination before a backup runs | US-001-02 | `API-RESIDENCY-174124` |
| Evaluate the CI residency gate per deploy | US-001-03 | `API-RESIDENCY-685134` |
| Report region and compliance status per component | US-001-04 | `API-RESIDENCY-913995` |
| Run the launch gate check | US-001-05 | `API-RESIDENCY-648672` |
| Scan for drift after launch and alert DevOps; read scan results | US-001-06 | `API-RESIDENCY-922826`, `API-RESIDENCY-202775` |

**Not responsible for:**

- Application behaviour of notes, search or login. Those belong to `notes`, `search` and `auth`.
- The OpenAPI document and its residency note (US-004-06, BR-013). That belongs to `contract-docs`.
- Residency of login emails (NFR-017). That is an `auth` concern.
- Human sign-off of the launch gate (BR-003 Enforcement: "Launch gate sign-off by Engineering Lead"). This module computes a verdict only (`CON-BE-257`).
- Creating cloud resources. Region constraints in infrastructure-as-code are the BR-001 enforcement. Whether the provisioning operation also creates anything is open (`GAP-BE-272`).
- Defining the approved region list. It is data, and no input supplies it (`GAP-BE-267`).
- The identity mechanism for callers. That depends on `backend.auth-model`, which is BLOCKED on `Q-BE-003` (`GAP-BE-278`).

## Data model

Persistence is in the notes_api PostgreSQL 16 database (`platform.md`; `ASM-BE-264`). Conventions under `ASM-BE-264`: identifiers are `uuid` generated by the database, timestamps are `timestamptz` in UTC, and every foreign key is `ON DELETE RESTRICT` because no input defines deletion of residency records (`GAP-BE-273`). No column holds PII, money or a credential.

|---|---|---|---|---|
| `region_code` | text | NOT NULL | none | PRIMARY KEY |
| `added_at` | timestamptz | NOT NULL | `now()` | none |

The table is empty until the region list is supplied (`GAP-BE-267`). Every comparison in this module reads this table, so no region is hard-coded.

## State machine

Two stored entities have a status column. Nothing in the listed operations lets a caller set a state directly. All transitions are made by this module (`ASM-BE-272`).

### Scan (`residency_scans.state`)

States: `running`, `completed`, `failed`. Terminal: `completed`, `failed`.

| From | To | Trigger | Guard |
|---|---|---|---|
| (new) | `running` | `API-RESIDENCY-922826`, `API-RESIDENCY-685134` or `API-RESIDENCY-648672` accepted | none |
| `running` | `completed` | every in-scope resource has a result row | counts sum to `total_count`; `verdict` set; `completed_at` set |
| `running` | `failed` | inventory unreadable, or internal error | `completed_at` set; `verdict` stays NULL |

A `failed` scan never counts as a pass. A gate caller treats it as blocked, by the same reasoning as AC-001-03-03 (`ASM-BE-266`).

Illegal transitions, such as anything out of a terminal state, are rejected inside the module and logged. No API status is defined for them because no operation can request one (`ASM-BE-272`).

### Alert (`residency_alerts.delivery_state`)

States: `pending`, `sent`, `failed`. Terminal: `sent`, and `failed` for now.

| From | To | Trigger | Guard |
|---|---|---|---|
| (new) | `pending` | scan completes with a `fail` result for a resource | one alert per `(scan, resource)` |
| `pending` | `sent` | delivery to DevOps succeeds | `sent_at` set |
| `pending` | `failed` | delivery fails | none |

`failed` could return to `pending` only under a retry policy, and none is stated (`GAP-BE-270`).

### Launch gate (derived, not stored)

The gate is "passed" when the latest completed `launch-gate` scan has verdict `pass`. Otherwise it is "failed" and release is blocked until a later check passes (AC-001-05-01, AC-001-05-02). A past verdict is never changed; a new check creates a new scan (`ASM-BE-273`).

## Requirements

Per-resource status values (`pass`, `fail`, `unverified`) are defined in `ASM-BE-265`. The approved list is `residency_approved_regions` (`GAP-BE-267`).

**BE-RESIDENCY-FR-001 — Accept provisioning in an approved EU region**
- Given a provisioning request whose target region is in the approved EU list, when it is submitted, then the request is accepted and recorded with outcome `accepted`.
- **Traces to.** US-001-01; AC-001-01-01; BR-001
- **Verification.** `residency.provisioning.accepts_eu_region` (planned)
- **API.** `API-RESIDENCY-026899`

**BE-RESIDENCY-FR-002 — Refuse provisioning in a non-EU region**
- Given a provisioning request whose target region is not in the approved EU list, when it is submitted, then it is rejected with a residency violation error, no resource is created and none is recorded.
- **Traces to.** US-001-01; AC-001-01-02; BR-001
- **Verification.** `residency.provisioning.rejects_non_eu_region` (planned)
- **API.** `API-RESIDENCY-026899`

**BE-RESIDENCY-FR-003 — Refuse provisioning when the region is absent or unrecognised**
- Given a provisioning request with no region or an unrecognised region value, when it is submitted, then it is rejected as in FR-002. This is derived from BR-001 "exclusively in approved EU regions", with fail-closed handling as in AC-001-03-03.
- **Traces to.** US-001-01; BR-001
- **Verification.** `residency.provisioning.rejects_missing_region` (planned)
- **API.** `API-RESIDENCY-026899`

**BE-RESIDENCY-FR-004 — Accept an EU backup destination**
- Given a backup destination in an approved EU region, when it is validated, then validation passes and the backup may proceed, so the artifact lands in EU storage.
- **Traces to.** US-001-02; AC-001-02-01; BR-001
- **Verification.** `residency.backup.accepts_eu_destination` (planned)
- **API.** `API-RESIDENCY-174124`

**BE-RESIDENCY-FR-005 — Fail a non-EU backup destination fast**
- Given a backup destination outside the EU, when validation runs before the backup, then the job fails within 30 seconds with a residency violation error and writes no data.
- **Traces to.** US-001-02; AC-001-02-02
- **Verification.** `residency.backup.rejects_non_eu_within_30s` (planned)
- **API.** `API-RESIDENCY-174124`

**BE-RESIDENCY-FR-006 — CI gate passes when all targets are EU**
- Given a deployment whose target resources are all in EU regions, when the gate is evaluated, then the verdict is `pass` and the deployment proceeds.
- **Traces to.** US-001-03; AC-001-03-01; BR-002
- **Verification.** `residency.ci_gate.passes_all_eu` (planned)
- **API.** `API-RESIDENCY-685134`

**BE-RESIDENCY-FR-007 — CI gate fails on any non-EU target**
- Given a deployment with at least one target resource outside the EU, when the gate is evaluated, then the verdict is `fail`, the build fails and the deployment is blocked.
- **Traces to.** US-001-03; AC-001-03-02; BR-002; NFR-002
- **Verification.** `residency.ci_gate.fails_any_non_eu` (planned)
- **API.** `API-RESIDENCY-685134`

**BE-RESIDENCY-FR-008 — CI gate fails closed on missing region metadata**
- Given a target resource whose region metadata is missing or unreadable, when the gate is evaluated, then that resource is `fail` and the verdict is `fail`. It never passes by default.
- **Traces to.** US-001-03; AC-001-03-03
- **Verification.** `residency.ci_gate.fails_on_missing_region` (planned)
- **API.** `API-RESIDENCY-685134`

**BE-RESIDENCY-FR-009 — Compliance report content**
- Given all resources exist and have been scanned, when the report is requested, then it lists each resource with its region and a `pass`, `fail` or `unverified` status, plus an overall percent compliant.
- **Traces to.** US-001-04; AC-001-04-01; NFR-001; NFR-004
- **Verification.** `residency.report.lists_all_resources_with_percent` (planned)
- **API.** `API-RESIDENCY-913995`

**BE-RESIDENCY-FR-010 — Unrecognised resource type is flagged, not omitted**
- Given a resource whose type the scanner does not recognise, when the report is generated, then the resource appears with status `unverified`.
- **Traces to.** US-001-04; AC-001-04-02
- **Verification.** `residency.report.flags_unrecognised_type_unverified` (planned)
- **API.** `API-RESIDENCY-913995`

**BE-RESIDENCY-FR-011 — Launch gate passes at 100%**
- Given the refreshed report shows 100% EU-verified resources, when the launch gate check runs, then the gate is marked passed and release is authorised.
- **Traces to.** US-001-05; AC-001-05-01; BR-003
- **Verification.** `residency.launch_gate.passes_at_100_percent` (planned)
- **API.** `API-RESIDENCY-648672`

**BE-RESIDENCY-FR-012 — Launch gate fails below 100%**
- Given the refreshed report shows less than 100% EU-verified resources (an `unverified` resource counts as not verified, `ASM-BE-265`), when the launch gate check runs, then the gate is marked failed and release is blocked until a later check passes.
- **Traces to.** US-001-05; AC-001-05-02; BR-003
- **Verification.** `residency.launch_gate.fails_below_100_percent` (planned)
- **API.** `API-RESIDENCY-648672`

**BE-RESIDENCY-FR-013 — Launch gate refreshes the report**
- Given a launch gate check is requested, when it runs, then it scans the full inventory first, so the report it reads is current.
- **Traces to.** US-001-05; NFR-004 ("Report refreshed and 100% accurate at each launch gate check")
- **Verification.** `residency.launch_gate.refreshes_report_before_verdict` (planned)
- **API.** `API-RESIDENCY-648672`; `API-RESIDENCY-913995`

**BE-RESIDENCY-FR-014 — Clean drift scan raises no alert**
- Given a drift scan runs and every resource is in an EU region, when it completes, then no alert is raised and the scan logs a pass.
- **Traces to.** US-001-06; AC-001-06-01
- **Verification.** `residency.drift.pass_raises_no_alert` (planned)
- **API.** `API-RESIDENCY-922826`

**BE-RESIDENCY-FR-015 — Drift raises an alert within 15 minutes**
- Given a drift scan finds a resource in a non-EU region, when it completes, then an alert with the resource details is sent to DevOps, no later than 15 minutes after detection.
- **Traces to.** US-001-06; AC-001-06-02; BR-004; NFR-003
- **Verification.** `residency.drift.non_eu_alerts_within_15_minutes` (planned)
- **API.** `API-RESIDENCY-922826`

**BE-RESIDENCY-FR-016 — Read a drift scan result**
- Given a drift scan exists, when its result is requested by id, then its state, counts and per-resource results are returned. An unknown id is reported as not found.
- **Traces to.** US-001-06
- **Verification.** `residency.drift.get_returns_result_or_not_found` (planned)
- **API.** `API-RESIDENCY-202775`

**BE-RESIDENCY-FR-017 — A scan that cannot read the inventory never passes**
- Given the inventory or its region metadata cannot be read, when a scan runs, then the scan ends `failed` and every gate caller treats it as blocked.
- **Traces to.** US-001-03 (AC-001-03-03, applied to the whole inventory); US-001-05; `ASM-BE-266`
- **Verification.** `residency.scan.unreadable_inventory_never_passes` (planned)
- **API.** `API-RESIDENCY-685134`; `API-RESIDENCY-648672`; `API-RESIDENCY-922826`

**BE-RESIDENCY-FR-018 — No credential or PII is stored or logged**
- Given a backup destination or provisioning request carries a credential, when it is processed, then the credential is neither stored nor logged and only a reference is kept.
- **Traces to.** Core section 12 (standing security constraints); NFR-018 (log safety, applied by extension)
- **Verification.** `residency.security.no_credential_persisted_or_logged` (planned)
- **API.** `API-RESIDENCY-174124`; `API-RESIDENCY-026899`

## Invariants

- **INV-BE-251.** A `pass` result means the observed region was in `residency_approved_regions` at scan time. A NULL or unlisted region is never `pass`. (BR-001; AC-001-03-03)
- **INV-BE-252.** A completed `drift` or `launch-gate` scan has one result row for every resource in the inventory at scan start. No resource is silently omitted. (AC-001-04-02)
- **INV-BE-253.** A scan has verdict `pass` only if every result is `pass` and `total_count` is greater than zero. A `failed` scan has no `pass` verdict. (BR-002; BR-003; `ASM-BE-266`)
- **INV-BE-254.** A rejected provisioning request leaves no resource created or recorded, and `resource_id` is NULL. (AC-001-01-02)
- **INV-BE-255.** A backup validation of a non-EU destination returns failure within 30 seconds of the request and writes no backup data. (AC-001-02-02)
- **INV-BE-256.** For a completed scan, `pass_count + fail_count + unverified_count = total_count`.
- **INV-BE-257.** No credential, token or password is stored in any column or written to a log by this module. (Core section 12)
- **INV-BE-258.** A scan in a terminal state (`completed`, `failed`) is never modified. A new check creates a new scan.
- **INV-BE-259.** An alert exists only for a resource with a `fail` result in its scan, at most one per `(scan, resource)`. (AC-001-06-01; AC-001-06-02)
- **INV-BE-260.** An `unverified` result is never counted as `pass` in any percent or verdict. (AC-001-04-02; AC-001-05-02)

## Test plan

**Unit**

- Region classification: a region in the approved list gives `pass`, an unlisted region gives `fail`, a NULL region gives `fail`, and an unrecognised resource type gives `unverified` (FR-001 to FR-003, FR-008, FR-010).
