## Purpose

**Responsible for** (module map `backend.module-map`; `stories.md`; `requirements.md`):

- Creating, reading and editing a note's title, body and `pinned` flag (US-002-01, US-002-02, US-002-06; BR-005, BR-006, BR-018).
- Archiving and unarchiving a note. Archiving is a flag and never deletes data, and unarchiving restores the note intact (US-002-04, US-002-05; BR-007, BR-008).
- Adding and removing tags on a note, with no duplicate tag on one note (US-002-03).
- The backend side of the web_app stories US-006-02, US-006-04 and US-006-05, by serving the operations listed in `scope`.

**Not responsible for:**

- Search, filtering, pagination and ordering of results, including pinned-first ordering. These belong to `search` (BR-019).
- Listing notes. No operation in this module lists active or archived notes (`GAP-BE-005`).
- Issuing or verifying login codes, which belongs to `auth`.
- The error envelope, the status-code policy and the registry code names. These are defined in `backend.error-model` and only referenced here.
- Refusal of attachment, real-time or mobile calls. This is `scope-guard`'s concern. This module returns 415 for a non-JSON payload on its write operations, and the response body shape is owned elsewhere.
- Publishing the OpenAPI document (`contract-docs`).
- Any web_app screen.
- Hard deletion of notes. No input defines one (BR-007, `GAP-BE-023`).

## Data model

Store: PostgreSQL 16 in an EU region (`platform.md`; BR-001). Migrations 001 and 002 in `backend.migration-plan` create these tables. Migration 007 (ownership) is not specified and is blocked on `Q-BE-002`.

### Table `notes`

| Column | Type | Null | Default | Constraint |
|---|---|---|---|---|
| `id` | uuid | NOT NULL | generated by the service | primary key; immutable (`ASM-BE-017`) |
| `title` | text | NOT NULL | none | non-empty (BR-005; `ASM-BE-024`) |
| `body` | text | NOT NULL | none | non-empty (BR-005; `ASM-BE-024`) |
| `pinned` | boolean | NOT NULL | `false` | BR-018 |
| `status` | text | NOT NULL | `'active'` | one of `'active'`, `'archived'` (`ASM-BE-018`) |
| `created_at` | timestamptz | NOT NULL | now(), UTC | never changes after insert (`ASM-BE-019`) |
| `updated_at` | timestamptz | NOT NULL | now(), UTC | refreshed per `ASM-BE-019` |

`NOT NULL` on `title` and `body` is a decision taken from BR-005: "empty/null payloads are rejected". No maximum length for either is stated (`GAP-BE-020`).

### Table `note_tags`

| Column | Type | Null | Default | Constraint |
|---|---|---|---|---|
| `note_id` | uuid | NOT NULL | none | foreign key to `notes.id`, `ON DELETE RESTRICT` (`ASM-BE-020`) |
| `tag_name` | text | NOT NULL | none | non-empty; compared exactly as supplied (`ASM-BE-021`) |

- Primary key is (`note_id`, `tag_name`). This enforces "no duplicate tag entry" on one note (US-002-03).
- Tag rules beyond that (case, charset, length, maximum count) are unstated (`GAP-BE-010`, `ASM-BE-021`, `ASM-BE-030`).

### Indexes

| Index | Query it serves |
|---|---|
| `notes` primary key on `id` | get, edit, archive, unarchive by id |
| `note_tags` primary key on (`note_id`, `tag_name`) | list a note's tags, check for an existing tag, add and remove a tag |

The tag lookup index and the full-text index serve the search queries. They are created by the `search` module (migration 003) and are not defined here.

### Other columns

- Timestamps are `timestamptz` stored in UTC (`ASM-BE-019`).
- No column in this module is marked as PII by any input. Whether note content is sensitive, and any at-rest treatment, is not stated (`GAP-BE-006`).
- No money or currency columns exist.

## State machine

A note's `status` has two states: `active` and `archived` (BR-007, BR-008; US-002-05 "status changes to active"). `pinned` is a separate boolean and does not change the state.

| From | Trigger | Guard | To | Result |
|---|---|---|---|---|
| (none) | `API-NOTES-232390` | valid payload | `active` | 201 |
| `active` | `API-NOTES-810640` | note exists | `archived` | 200; all data kept |
| `archived` | `API-NOTES-917869` | note exists | `active` | 200; all data restored intact |

**Illegal or no-op transitions**

| Situation | Outcome | Source |
|---|---|---|
| Archive a note that is already `archived` | 409, code `NOTE_ALREADY_ARCHIVED` | US-002-04 AC2; `backend.error-model` |
| Unarchive a note that is already `active` | 200, note unchanged. This is a no-op under `ASM-BE-022`. | `ASM-BE-022`, `Q-BE-005` |
| Archive or unarchive an unknown id | 404, code `NOTE_NOT_FOUND` | US-002-05 AC2; `ASM-BE-025` |

**Terminal states.** None. Archiving is fully reversible (BR-008), and there is no deleted state (`GAP-BE-023`).

**Operations permitted in each state.** Get, edit, add tag and remove tag are permitted in both states (`ASM-BE-023`, `Q-BE-004`). Their status results do not depend on `status`.

**Badge derivation.** The archived/active indicator a client shows is a function of `status` alone. No input derives it from another field.

### Assumptions

| ID | Assumption |
|---|---|
| `ASM-BE-017` | The note id is a uuid. The stories say only "unique ID" (US-002-01). |
| `ASM-BE-018` | `status` is a text column constrained to `active` or `archived`, defaulting to `active`. The inputs say only "archive flag" (BR-007) and "status changes to active" (US-002-05). |
| `ASM-BE-019` | Timestamps are `timestamptz` in UTC. `updated_at` is refreshed on any change to title, body, `pinned`, the tag set or `status` (`GAP-BE-021`). |
| `ASM-BE-020` | `note_tags.note_id` references `notes.id` with `ON DELETE RESTRICT`, because no input defines hard delete (`GAP-BE-023`). |
| `ASM-BE-021` | Tag names are non-empty and compared exactly as supplied: case-sensitive, no trimming or normalisation. A tag in a DELETE path is URL-decoded before comparison. |
| `ASM-BE-022` | Unarchiving an already-active note returns 200 with the note unchanged. The operation record lists no 409 for it (`Q-BE-005`). |
| `ASM-BE-023` | Edits and tag changes are allowed on archived notes. No input forbids them (`Q-BE-004`). |
| `ASM-BE-024` | Create and edit validation treats an empty or whitespace-only title or body as invalid. An unknown field, a non-boolean `pinned`, or an empty PATCH body returns 400 `VALIDATION_ERROR`. |
| `ASM-BE-025` | Tag add returns 200 whether the tag is new or repeated. Tag removal returns 200 for a present or absent tag. Both return 404 for an unknown note, and add returns 400 for an empty tag name. Archive of an unknown note returns 404 by analogy with US-002-05. |
| `ASM-BE-026` | A note's tags are returned in ascending order of name, so responses are deterministic. No input states an order. |
| `ASM-BE-027` | Create with tags is atomic, and duplicate tag names within one request are stored once. |
| `ASM-BE-028` | A path id that is not a valid uuid returns 400 `VALIDATION_ERROR` (depends on `ASM-BE-017`). |
| `ASM-BE-029` | Concurrent edits are last-write-wins, with no version column (US-005-03 AC2; `GAP-BE-022`). |
| `ASM-BE-030` | There is no maximum number of tags per note (`Q-BE-006`). |
