# TC-003-19: Keyword search returns pinned first

**Story:** [[US-003-01]]
**Module:** search notes by keyword across title and content
**Kind:** api

## Preconditions
notes exist matching the keyword

## Expected Result
matching notes are returned with pinned notes first, then ordered by relevance, with 200 status

## Acceptance Criteria
- notes_api:AC-003-01-01: Given notes exist matching the keyword, when GET /notes/search?q=keyword is called, then matching notes are returned with pinned notes first, then ordered by relevance, with 200 status

## Planned API Steps

| # | Instruction | Action | Target | Value |
|---|---|---|---|---|
| 1 | Create unpinned match | request | `POST /notes` | {"title":"zebrakw plain","body":"zebrakw zebrakw"} |
| 2 | Create pinned match | request | `POST /notes` | {"title":"zebrakw pinned","body":"b","pinned":true} |
| 3 | Search | request | `GET /notes/search?q=zebrakw` |  |
| 4 | OK | assert_status | `status` | 200 |
| 5 | Pinned first | assert_json | `$.items[0].pinned` | true |
| 6 | Second is unpinned | assert_json | `$.items[1].pinned` | false |
