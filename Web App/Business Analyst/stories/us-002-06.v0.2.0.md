# US-002-06: receive paginated search results

## Definition

As a **team member performing a large or frequent search**, I want to **receive paginated search results**, so that **search stays fast and low-latency at scale, protecting the <=300ms median latency target**.

**Epic:** [[EP-002]]

## Acceptance Criteria
- [[AC-002-06-01]] — Given a search query matches more results than the page size, when client requests a page via page/limit parameters, then API returns 200 with the correct page of results and total count
- [[AC-002-06-02]] — Given a requested page number beyond available results, when client calls search with that page number, then API returns 200 with an empty result list and correct total count
- [[AC-002-06-03]] — Given a negative or non-numeric page or limit parameter, when client calls search endpoint, then API returns 400 with a validation error
