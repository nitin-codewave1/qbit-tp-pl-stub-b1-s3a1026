# US-005-05: maintain a documented out-of-scope list (attachments, mobile-specific endpoints, real-time) in the API spec

## Definition

As a **product owner**, I want to **maintain a documented out-of-scope list (attachments, mobile-specific endpoints, real-time) in the API spec**, so that **gives stakeholders a clear reference to prevent reintroducing descoped features later**.

**Epic:** [[EP-005]]

## Acceptance Criteria
- [[AC-005-05-01]] — Given the published API documentation, when a reader views the scope section, then attachments, mobile endpoints, and real-time features are explicitly listed as out of scope
- [[AC-005-05-02]] — Given a future contributor proposes an attachment endpoint, when they check the documented out-of-scope list first, then they see the feature is explicitly excluded before writing code
