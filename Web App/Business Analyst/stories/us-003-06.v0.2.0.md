# US-003-06: receive consistent error handling for malformed archive/unarchive requests

## Definition

As a **operations engineer validating reliability**, I want to **receive consistent error handling for malformed archive/unarchive requests**, so that **ensure high success rate of archive calls as measured by the KPI**.

**Epic:** [[EP-003]]

## Acceptance Criteria
- [[AC-003-06-01]] — Given an archive request is sent with a malformed note id (non-UUID or invalid format), when client calls archive endpoint, then API returns 400 with a descriptive error body
- [[AC-003-06-02]] — Given an unarchive request is sent with an empty id field, when client calls unarchive endpoint, then API returns 400 without server error
