# US-003-01

As a team member closing out finished work, I want to archive a note via the API, so that remove completed notes from active view without deleting data, supporting lifecycle KPI. - Given an active note with a valid id exists, when client calls archive endpoint for that note, then API returns 200 and note status is set to archived, content unchanged - Given note id does not exist, when client calls archive endpoint, then API returns 404 with error body - Given note is already archived, when client calls archive endpoint again, then API returns 200 idempotently without error or state change - Test case: client calls archive endpoint for that note - Test case: [error] client calls archive endpoint - Test case: [edge] client calls archive endpoint again
