# US-005-01

As a API tech lead, I want to define the API surface with exactly 5 endpoint groups (create, edit, tag, search, archive note), so that keeps final endpoint count matching brief-defined scope, directly measuring the KPI. - Given the API spec is generated, when all routes are listed, then only routes for create, edit, tag, search, and archive note exist - Given a developer proposes a new route outside the 5 capabilities, when the route is added to the codebase, then the spec-compliance check fails the build - Test case: all routes are listed - Test case: [error] the route is added to the codebase
