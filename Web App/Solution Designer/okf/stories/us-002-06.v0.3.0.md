# US-002-06

As a team member performing a large or frequent search, I want to receive paginated search results, so that search stays fast and low-latency at scale, protecting the <=300ms median latency target. - Given a search query matches more results than the page size, when client requests a page via page/limit parameters, then API returns 200 with the correct page of results and total count - Given a requested page number beyond available results, when client calls search with that page number, then API returns 200 with an empty result list and correct total count - Given a negative or non-numeric page or limit parameter, when client calls search endpoint, then API returns 400 with a validation error - Test case: client requests a page via page/limit parameters - Test case: [edge] client calls search with that page number - Test case: [error] client calls search endpoint
