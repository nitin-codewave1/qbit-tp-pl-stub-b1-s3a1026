# US-005-03

As a API tech lead, I want to ensure no WebSocket, SSE, or polling-for-live-updates endpoints are exposed, so that keeps the build free of real-time collaboration features not in brief scope. - Given the API's route registry is inspected, when checked for protocol types, then only standard HTTP request/response endpoints are present - Given a pull request adds a WebSocket or SSE route, when CI scope-guardrail check runs, then the check fails and blocks merge - Test case: checked for protocol types - Test case: [error] CI scope-guardrail check runs
