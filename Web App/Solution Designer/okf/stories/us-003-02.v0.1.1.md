# US-003-02

As a team member resuming old work, I want to restore (unarchive) a previously archived note via the API, so that bring a note back to active status without data loss, supporting lifecycle KPI. - Given an archived note with a valid id exists, when client calls unarchive endpoint for that note, then API returns 200 and note status is set to active, content unchanged - Given note id does not exist, when client calls unarchive endpoint, then API returns 404 with error body - Given note is already active, when client calls unarchive endpoint, then API returns 200 idempotently without error or state change - Test case: client calls unarchive endpoint for that note - Test case: [error] client calls unarchive endpoint - Test case: [edge] client calls unarchive endpoint
